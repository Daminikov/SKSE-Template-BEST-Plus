# Переводы / Translations

Одна папка, один файл на язык — и он переводит **всё**: страницу в меню (ApocryphaRealm Menu
Framework), веб-окно PrismaUI, любые сообщения мода. Разделять «тексты C++» и «тексты вьюхи» не
нужно: плагин отдаёт вьюхе ту же таблицу через `window.applyTranslations(json)`.

## Что делать переводчику

1. Взять `english.txt` как образец (или создать заготовку: `python tools/new_language.py german`).
2. Менять **только текст после табуляции**. Ключ (например `$MyPlugin_Settings_DebugLogging`)
   — это контракт с кодом, его нельзя переименовывать, удалять и дописывать.
3. Не добавлять и не удалять строки: если строки нет, мод покажет английский фолбэк, а проверка
   пожалуется на missing key.
4. Не вписывать `%`-последовательности руками. Если в английском тексте есть `%s`/`%02X` — их
   должно быть столько же в переводе (проверка это ловит).
5. Подготовить файл: `python tools/check_translations.py` — должен быть `OK`.

## Формат (не менять)

| Что | Значение |
|---|---|
| Кодировка | UTF-16 LE **с BOM** (`FF FE`) |
| Переводы строк | CRLF |
| Строка | `$Ключ<TAB>текст` (ровно один табулятор) |
| Комментарии | не поддерживаются — строки без `$` игнорируются, но лучше их не оставлять |

Файлы генерируются скриптами (`tools/make_translations.py`, `tools/new_language.py`), потому что
редакторы и буфер обмена регулярно портят кодировку и переводы строк.

## Куда попадает файл

`translations/<язык>.txt` → при сборке `<Мод>\Interface\Translations\<Мод>_<язык>.txt`.

Это родное место интерфейсных переводов Skyrim. Из него же ApocryphaRealm Menu Framework собирает
атлас шрифта: символы (кириллица, кана, хангюль, ханьцзы) из любого `<что угодно>_<язык>.txt`
попадают в атлас для этого языка автоматически — рисовать шрифты моду не нужно.

## Как проверить живьём

Язык мода = язык, выбранный в настройках фреймворка (`AMF_GetLanguage()`), а не версия игры.
Переключение языка в Framework Settings применяется **на ходу, без перезапуска**: страница и
веб-окно перерисовываются, лог пишет `localization: language changed to <язык>`.

Незакрытые ключи видны в логе мода: `localization: missing key $... for language <язык>`.

## Добавить язык целиком

```bash
python tools/new_language.py german     # заготовка со всеми ключами
# перевести значения
python tools/check_translations.py      # формат + покрытие по всем языкам
cmake --build build/release             # сборка сама задеплоит все translations/*.txt
```

Список языков деплоя не задаётся вручную: сборка забирает **все** `translations/*.txt`.
